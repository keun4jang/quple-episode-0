# 재설치 없는 자동 갱신 (OTA)

앱을 지우거나 APK 를 다시 깔지 않아도, 우리가 고친 내용이 폰에 반영된다.

## 쓰는 법

```bash
tools/publish-update.sh 0.1.2
```

이 한 줄이 버전을 올리고, 리소스 팩을 만들고, manifest 를 쓰고, push 한다.
사용자는 앱을 껐다 켜기만 하면 된다.

## 어떻게 도는가

```
앱 실행
  └ AutoUpdate 가 제일 먼저 뜬다 (main scene 보다 먼저)
      ├ 지난번에 받아둔 팩이 있으면 → 얹는다. 이번 실행부터 새 내용.
      └ 백그라운드로 manifest 확인
          └ 새 버전이면 → 받아서 검증만 하고 저장. 다음 실행에 적용.
```

**받자마자 적용하지 않는다.** 이미 메모리에 올라간 씬과 새로 얹은 스크립트가
섞이면 재현도 안 되는 버그가 난다. 그래서 "이번엔 받아만 두고 다음에 적용" 이다.
결과적으로 사용자는 **앱을 두 번 켜면** 새 내용을 본다.

## 팩으로 바꿀 수 있는 것 / 없는 것

| 바꿀 수 있다 | 바꿀 수 없다 (APK 재배포 필요) |
|---|---|
| GDScript 전부 | Godot 엔진, 네이티브 라이브러리 |
| 씬, UI, 레이아웃 | 안드로이드 권한 |
| 대사, 여행지, 밸런스 | 앱 이름·아이콘·패키지명 |
| 셰이더, 머티리얼 | 화면 방향 등 `project.godot` 의 부팅 설정 |
| 이미지·폰트 등 리소스 | |

게임 로직은 거의 전부 GDScript 라 실무에서는 대부분 팩으로 해결된다.

## 안전장치

자기 자신을 갈아끼우는 기능이라, 잘못되면 앱이 영영 안 켜진다. 세 겹으로 막는다.

**1. 해시 검증** — manifest 의 `sha256` 과 받은 파일이 다르면 버린다.
받다 끊긴 파일이나 바꿔치기된 파일을 코드로 실행하지 않는다.

**2. 부팅 롤백** — 팩을 얹기 직전에 `boot_pending` 을 기록하고, 앱이 무사히
뜨면 지운다. 다음 실행 때 이 표시가 남아 있으면 = 지난번에 이 팩이 앱을 죽였다는
뜻이므로 팩을 지우고 APK 원래 내용으로 돌아간다. **이게 없으면 잘못된 패치
하나로 사용자가 앱을 지우는 것 말고는 방법이 없다.**

**3. 고정 주소** — `auto_update.gd` 의 `MANIFEST_URL` 에 박힌 저장소만 본다.
서버가 주는 주소로 아무 데나 따라가지 않는다.

## 알아둘 것

이건 **원격에서 코드를 받아 실행하는 통로**다. 저장소에 push 권한이 있는 사람은
누구나 사용자 폰에서 코드를 돌릴 수 있다는 뜻이다. 개인 프로젝트라 괜찮지만,
스토어에 올리고 사용자가 늘면 다음을 고려해야 한다.

- 서명 검증 추가 (manifest 에 개인키 서명 → 앱이 공개키로 확인).
  지금은 저장소가 공개라 **push 권한이 있는 사람이 곧 실행 권한**을 갖는다.
- 구글 플레이 정책: 실행 코드를 외부에서 받아 실행하는 것은 제한될 수 있다.
  플레이 배포 시에는 팩을 **데이터·에셋만**으로 좁히는 편이 안전하다.

## 브랜치

manifest 주소는 `claude/dreamy-heisenberg-gkeg9a` 브랜치를 가리킨다.
다른 브랜치에서 `publish-update.sh` 를 돌리면 폰이 못 받으므로 스크립트가 막는다.
브랜치를 바꾸려면 `auto_update.gd` 의 `MANIFEST_URL` 도 같이 고쳐야 한다.
