# 쿼플 재기획 — 단순한 여행 게임

> 상태: **기획안 (구현 전)**. 이 문서에 합의가 되면 그때 코드를 건드린다.

## 1. 지금 무엇이 복잡한가

숫자부터 본다.

| 덩어리 | 줄 수 | 화면 수 |
|---|---|---|
| 0편 횡스크롤 (`scripts/side/`) | 2,580 | 맵 4개 |
| 여행 (`scripts/travel/`) | 3,313 | 허브·앨범·기념품방·통계·도착연출 |
| UI (`scripts/ui/`) | 1,858 | 대화·선택·설정·튜토리얼·조이스틱·바람편지 |

**프롤로그가 본편보다 크다.** 0편은 원래 "왜 떠났는가"를 5분 안에 보여주는 장면이었는데,
점프·사다리·엘리베이터·계단·조이스틱·포탈·화면끝 화살표·13단계 상태머신이 붙으면서
그 자체로 하나의 게임이 됐다. 그리고 그 게임의 주제는 **여행이 아니라 회사 탈출**이다.

여행 쪽도 갈래가 많다. 여행지 225곳에 대륙 필터, 방문 필터, 앨범, 기념품 3D 방,
통계 화면, 바람편지, 엽서 내보내기. 하나하나는 좋은데 **"오늘 켜서 뭘 하지"** 의 답이
7가지가 되면 답이 없는 것과 같다.

핵심은 이렇다. `docs/core-loop.md` 의 한 문장 —

> 앱을 끄면 쿼카 커플이 여행을 다녀오고, 다시 켜면 그들이 찍어온 사진과 일기를 확인한다.

— 이건 이미 충분히 단순하다. 복잡한 건 **그 위에 얹힌 것들**이다.
그러니 코어 루프를 바꾸는 게 아니라, 코어 루프만 남긴다.

## 2. 바꿀 형식

### 한 줄

**조작하는 게임 → 들여다보는 게임.**

실시간 조작(걷기·점프·사다리)을 전부 없앤다. 플레이어가 하는 입력은
**보내기 / 열어보기** 두 가지다.

### 켜면 보이는 것

화면 하나. 스크롤도 탭 전환도 없다.

```
┌────────────────────────────┐
│   (하늘 — 지금 시각의 색)   │
│                            │
│      🚶🚶  ← 쿼카 커플      │
│  ════════════════════════  │  ← 문 앞 (집)
│                            │
│  [ 어디로 보낼까요? ]       │  ← 여행 중이면 남은 시간
└────────────────────────────┘
```

상태는 셋뿐이고, 지금 코드의 `IDLE / TRAVELING / ARRIVED` 를 그대로 쓴다.

| 상태 | 화면 | 플레이어가 하는 일 |
|---|---|---|
| 집에 있음 | 쿼카 둘이 문 앞에 앉아 있다 | 카드 **3장** 중 하나를 고른다 |
| 여행 중 | 문 앞이 비어 있다 | 아무것도 안 한다. 남은 시간만 본다 |
| 돌아옴 | 둘이 걸어 들어온다 | 사진 1장 + 일기 1줄을 받는다 |

### 여행지 고르기 — 목록을 없앤다

지금: 225곳 목록 + 대륙 필터 + 방문 필터.
바꿈: **카드 3장.** 매번 안 가본 곳에서 뽑는다. 목록도 필터도 검색도 없다.

225곳은 그대로 둔다. **데이터는 남기고 UI만 없앤다.** 뽑기 풀로 쓰면 되고,
"안 가본 곳" 필터가 하던 일은 뽑기가 알아서 한다.
막 해금(국내 5곳 → 해외, 해외 15곳 → 우주)도 뽑기 풀을 넓히는 것으로 그대로 산다.

### 사진첩 — 한 곳으로 합친다

지금: 앨범 + 기념품 3D 방 + 통계 + 바람편지 + 엽서 내보내기 = 화면 5개.
바꿈: **사진첩 하나.** 다녀온 사진이 격자로 쌓인다. 한 장 누르면 크게 + 일기 한 줄.

통계는 사진첩 맨 위 한 줄로 줄인다 — `다녀온 곳 38 / 225`.
기념품 3D 방·바람편지·엽서 내보내기는 뺀다.

### 0편 — 플레이하지 않고 본다

지금: 맵 4개를 걸어다니며 13단계를 진행 (10~15분).
바꿈: **픽셀 컷신 6장** + 짧은 문장. 넘기기만 한다. 약 90초.

| 컷 | 그림 | 문장 |
|---|---|---|
| 1 | 야근하는 사무실 창밖, 밤 | 또 막차였다. |
| 2 | 옆자리 애인 | "우리 그냥… 어디 갈까?" |
| 3 | 대표실 문틈 | "사람은 도구처럼 쓰면 돼." |
| 4 | 책상 위 카메라·수첩·가방 | 챙길 건 세 개뿐이었다. |
| 5 | 사원증을 반납함에 넣는 손 | 반납했다. |
| 6 | 회사 앞, 둘이 나란히 | 오늘은 퇴근이 아니라 출발이었다. |

이야기는 **한 줄도 안 바뀐다.** 대사와 순서는 `scripts/side/maps/*.gd` 에서 그대로 옮긴다.
0편에서 챙긴 물건 3개가 여행에 반영되는 규칙(카메라 없으면 사진 없음 등)도 유지 —
컷 4에서 자동으로 다 챙긴 것으로 친다.

## 3. 화풍 — 픽셀

`tools/pixel/pixelize.py` 로 확정. 내부 해상도 **480×216**, 쿼카 키 약 38px,
팔레트는 기존 에셋(`leader-front`, `partner-front`, `chapter-korea`, `hub-bg`)에서 뽑은 32색.

새로 그리는 게 아니라 **있는 그림을 변환**한다. 화풍을 바꾸는 것이지 게임을 바꾸는 게 아니다.
비용이 드는 이미지 생성은 쓰지 않는다.

## 4. 남기고 / 버리는 것

### 남긴다
- 오프라인 진행 (`Time.get_unix_time_from_system()` 기준) — 이 게임의 심장
- 여행지 225곳 데이터, 막 구조, 해금 조건
- 기념품·소식 자동 생성 (`_auto_souvenir`, `_auto_messages`)
- 돌아옴 연출 (`arrival_scene.gd`) — 다시 켤 이유를 만드는 유일한 장치
- 기다린 만큼 쪽지가 쌓이는 규칙
- 저장·자동갱신·설정
- 0편 이야기와 대사 전부

### 버린다
- 횡스크롤 이동 전체 (걷기·점프·사다리·엘리베이터·계단·조이스틱·포탈) — 2,580줄
- 실내 배경 4장 (컷신 배경으로 일부 재활용 가능)
- 여행지 목록 화면과 필터
- 기념품 3D 방 (602줄), 통계 화면 (398줄), 바람편지, 엽서 내보내기
- 튜토리얼 (조작이 없어지면 가르칠 게 없다)

대략 **4,000줄 이상**이 빠지고 화면은 12개에서 4개(집·사진첩·설정·컷신)로 준다.

### 애매한 것 — 여행 중 중간 소식
지금은 35%·70% 지점에 소식이 온다. 기다리는 시간을 채워 주지만,
"안 읽은 소식 N개" 배지는 할 일을 하나 더 만드는 쪽이다.
→ **배지는 없애고 소식은 남긴다.** 여행 화면을 열면 그냥 거기 있는다.

## 5. 왜 이게 나은가

- 켜서 하는 일이 **하나**다. 보내거나, 받거나.
- 조작이 없으니 손이 작은 화면에서도 되고, 세로 한 손으로 된다.
- 이야기 주제(여행)와 플레이(여행 보내기)가 처음으로 일치한다.
- 유지할 코드가 3분의 1로 준다. 1인 개발에서 이게 제일 크다.

## 6. 대가 — 정직하게

- 어제 만든 플랫포머(2,580줄)와 여기 붙은 테스트가 대부분 버려진다.
- 제미나이로 뽑으신 실내 배경 4장은 컷신 배경으로만 일부 쓰인다.
- 3D 기념품 방을 버리므로 "모아서 꾸미는" 재미가 사라진다.
  나중에 사진첩 안에서 2D로 다시 붙일 수는 있다.
- **되돌리기 어렵다.** 지운 코드는 git에 남지만, 다시 살리려면 픽셀 화풍에 맞춰
  전부 다시 손봐야 한다.

## 7. 하게 되면 순서

1. 픽셀 변환 파이프라인을 실제 에셋에 적용 (`tools/pixel/pixelize.py`)
2. 집 화면 하나로 재구성 — 카드 3장 뽑기
3. 사진첩 통합, 나머지 화면 제거
4. 0편을 컷신 6장으로 교체, 횡스크롤 삭제
5. 테스트 정리 — 코어 루프 68개는 살고, 횡스크롤 테스트는 지운다
6. 시뮬레이션 다시 돌려 처음~클리어 확인
