### 확인하지 못한 것 (상상해서 적지 않는다)

- **퀘스트 시스템 코드는 존재하지 않는다.** `docs/quest-journey.md`에 설계만
  있고, `JourneyState`나 `Place`에 `quests`류 필드·함수는 아직 없다
- 실제 세이브 파일 예시(런타임에 기기에 생기는 것이라 저장소엔 없다)
- 폰 실기에서의 최신 스크린샷(문서 속 스크린샷은 과거 것일 수 있다)
- 이번에 언급된 새 이미지(`Gemini_Generated_Image_52cstq52cstq52cs.jpg`)는
  **저장소 어디에도 없다** — main 브랜치 루트에는 과거에 올린 7장만 있다
- 데이터 파일(JSON/CSV/.tres) 형태의 콘텐츠 정의는 **하나도 없다.** 대사·
  편지·퀘스트가 전부 GDScript 배열/딕셔너리로 코드 안에 직접 적혀 있다

## 1. 핵심 규칙 체크리스트

- **게임 톤**: 벌 없음, 실패 없음, 광고·IAP·개인정보 수집 없음. 막히거나
  불안해지는 구조 금지
- **지명 규칙**: 순우리말 신조 지명만. 실존 지명 절대 금지. 고향은 끝까지
  이름 없음. 새 지명 후보는 전부 "실존 지명 검수 필요"로 표시
- **쿼- 접두사**: 쿼카가 만든 것에만. 자연·몸·마음·동작·가족호칭·지명·
  "행복"엔 안 붙임. 대사 한 줄에 하나, 화면 하나에 둘까지
- **제목 문구("진짜 행복") 사용 규칙**: 게임 전체에서 **딱 두 번.**
  **이미 코드에 둘 다 구현돼 있다** (2-5절 참고) — 새로 추가하면 안 된다
- **퀘스트 규칙**: 마을 클리어 시 다음 마을 오픈(고향 예외), 기존 행동만
  재사용, 숫자 진행률 노출 금지, 너구리 필수화 금지, 마을당 5~6개, 10분 안쪽
- **NPC 규칙**: 물범(가게)·갈매기(먼 곳 동경)·너구리(재회, 선택) 패턴
- **아트 규칙**: 16px 타일, 정면 픽셀, 24px 캐릭터, 45도/아이소메트릭 금지

### 패턴 유지 vs 신규 추가 판단

1. **1탄은 물범/갈매기 패턴 유지**의 장점: 이미 만든 인프라(시간표,
   대사 배열, 도어 시스템)를 그대로 재사용, 학습비용 없음, 넷 마을이
   "같은 나라를 여행 중"이라는 일관성을 준다
2. **2탄부터 선택형 세 번째 NPC 추가**의 장점: 새 지역마다 다른 종이
   있으면 "다른 지방에 왔다"는 지리적 신선함이 생긴다. 필수화만 안 하면
   위험이 없다
3. **새 NPC를 필수 퀘스트에 넣을 때의 위험**: 너구리 사례와 동일 —
   위치·등장이 저장 상태·시간대에 따라 달라지면 진행이 막힐 수 있다.
   필수 NPC는 **항상 같은 자리에 있는 붙박이**만 자격이 있다
4. **선택형 관계·편지·서브 대화로 둘 때의 장점**: 부담 없이 발견하는
   재미, 편지 발신인 목록을 늘릴 수 있음, 진행을 막지 않으면서 세계를
   넓힘

**권장안**: 1탄(국내) 나머지 신규 마을들도 물범/갈매기 패턴을 유지하고,
**너구리 자리에 마을마다 다른 선택형 카메오 동물**(아래 표)을 하나씩
슬쩍 끼워 넣는 절충안을 제안한다. 필수 퀘스트엔 안 넣는다.

## 7. 실제 구현 단계 제안

### 데이터로 분리할 수 있는 항목

- 마을별 편지·엽서 문구 — 지금은 없거나(`letters`) `journey_state.gd`
  안에 흩어져 있다. 발신인이 12명으로 늘면 `Dictionary` 상수 하나로
  모으는 걸 권장 (새 리소스 포맷을 만들 필요는 없다, GDScript 상수로 충분)
- 마을별 퀘스트 정의 — `docs/quest-journey.md` 8절 제안대로 각
  `places/*.gd`에 `quests() -> Array`

### 새 시스템 없이 처리 가능한 항목

- 퀘스트 완료 판정 전부 (대화 횟수·줍기·방문·사진·자기·가게 들어가기는
  이미 있는 상태에서 매번 다시 계산 가능, 새 저장 필드 최소화)
- 지도/카메라 게이팅 — `JourneyState.bag`에 아이템만 추가, HUD는 개수
  확인 후 보이기/숨기기만

### 구현 전 확인해야 할 질문 (5개, `quest-journey.md` 9절과 통합)

1. 마을 순서(윤슬→볕뉘→가풀재→하늬섬) 고정 확정?
2. 기존 세이브(이미 진행 중인 사람)는 퀘스트·지도·카메라를 소급으로
   전부 가진 것으로 칠지?
3. 편지 12개(2-4절)를 어느 시점에 트리거할지 — 지금 `maybe_letter()`는
   방문 3곳 기준 공용 텍스트인데, 발신인별 개인화 편지로 바꾸면 트리거
   조건도 새로 정해야 한다
4. 2탄용 새 마을 12곳 중 실제로 몇 곳을 먼저 만들지, 순서는?
5. 신규 동물 NPC(5절)를 도입할지, 도입한다면 1탄에 슬쩍 카메오로
   끼울지 2탄부터로 미룰지?

### 리스크와 해결

| 리스크 | 해결 방향 |
|---|---|
| 기존 플레이어가 업데이트 후 갑자기 미니맵/카메라를 잃음 | 마이그레이션: 기존 세이브는 `map`/`camera` 자동 지급 |
