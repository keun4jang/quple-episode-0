# 쿼플 재기획 — 방치형 여행 게임

> 상태: **기획안 (구현 전)**.
> `docs/redesign-simple.md` 를 대체한다. 그 문서의 "단순하게" 방향은 유지하되,
> 코어 루프를 방치형으로 바꾼다.

## 0. 먼저 — 이 게임은 이미 반쯤 방치형이다

`TravelState` 는 이미 실제 시각(unix time)으로 진행한다. 앱을 꺼도 여행이 끝나 있다.
타이머를 돌리지 않으므로 배터리도 안 쓴다. **방치형의 심장은 이미 있다.**

없는 것은 셋이다.

1. **반복이 안 된다** — 여행 한 번 끝나면 멈춰 서서 사람을 기다린다
2. **쌓이는 게 없다** — 사진만 늘 뿐, 다음이 더 좋아지지 않는다
3. **성장이 없다** — 3일 한 것과 30일 한 사람의 화면이 같다

방치형으로 간다는 건 이 셋을 채운다는 뜻이다. 새로 만드는 게 아니라 **이어 붙이는 것**이다.

## 1. 코어 루프

```
    ┌─────────────────────────────────────────┐
    │                                         │
  출발  →  (앱을 꺼도 시간이 흐름)  →  돌아옴  →  여비·추억을 받는다
    ↑                                         │
    │                                         ↓
    └──────  자동 출발  ←─────  업그레이드로 더 멀리·더 빨리·더 많이
```

플레이어가 하는 일은 **하루 한두 번 켜서, 쌓인 걸 받고, 하나 올려 주는 것**이다.
한 번 체크인 30초~1분.

## 2. 자원 — 둘뿐

| 자원 | 어디서 | 무엇에 쓰나 | 성질 |
|---|---|---|---|
| **여비** 💰 | 여행 갔다 올 때마다 | 업그레이드 | 무한히 쌓임, 계속 쓰임 |
| **추억** ✨ | **처음 가는 곳**에서만 1개 | 영구 배율 (다시 떠나기) | 유한 — 총 225개 |

여비는 도는 자원, 추억은 남는 자원. 셋 이상은 안 만든다.

### 여비 계산

```gdscript
여비 = 기본값(막) × 카메라배율 × 가방수 × (1 + 재방문횟수 × 0.05)
```

| 막 | 기본 여비 | 여행 시간 |
|---|---|---|
| 국내 | 10 | 30분~1시간 30분 |
| 해외 | 60 | 1시간 30분~4시간 |
| 우주 | 400 | 6~10시간 |
| 다른 차원 | 5,000 | 24시간 |

먼 곳이 시간당 여비도 높다. **"더 멀리 가고 싶다"가 성장 동기**가 되게 한다.
막 해금 조건(국내 5곳 → 해외, 해외 15곳 → 우주, 우주 8곳 → 차원)은 지금 걸 그대로 쓴다.

## 3. 업그레이드 — 다섯 줄

한 화면에 다 들어가야 한다. 트리도 탭도 만들지 않는다.

| 업그레이드 | 하는 일 | 단계 | 시작 비용 |
|---|---|---|---|
| 🚲 **이동수단** | 여행 시간 −10%/단계 | 7 (도보→자전거→버스→기차→배→비행기→로켓) | 50 |
| 🎒 **가방** | 한 번에 가져오는 기념품 수 (=여비 배수) | 5 (1→5개) | 200 |
| 📷 **카메라** | 여비 ×1.25/단계 | 20 | 80 |
| 📓 **수첩** | 오프라인 정산 상한 2h→48h | 6 | 300 |
| 🗺 **여행 계획표** | **자동 출발** 해금 + 자동 선택 규칙 | 3 | 500 |

비용 곡선은 방치형 표준을 쓴다.

```gdscript
cost(level) = base * pow(1.15, level)
```

카메라 20단계면 여비 배율 ×86, 누적 비용 약 8,200. 이동수단 7단계면 여행 시간 −52%.
**이 둘이 곱해지는 순간이 방치형의 재미**다 — 반나절 만에 체감이 확 바뀐다.

이동수단은 픽셀 그림이 실제로 바뀐다. 자전거 타고 가는 쿼카, 기차 창가의 쿼카.
숫자만 오르는 게 아니라 **화면이 달라지는 성장**이어야 한다.

## 4. 오프라인 정산 — 방치형의 핵심

지금 코드는 여행 **1건**만 진행한다. 12시간 만에 켜도 30분짜리 여행 하나 끝나 있을 뿐이다.
방치형에서는 그 사이 여러 번 왕복해야 한다.

```gdscript
# 켤 때 한 번 계산한다. 타이머 없음.
var elapsed := min(now - last_seen, 수첩_상한_초)
var per_trip := 평균_여행시간 * 이동수단_배율
var trips := floori(elapsed / per_trip)
var 여비 := trips * 회당_여비
```

정산 결과는 **문 앞에 쌓인 것**으로 보여준다. 숫자 팝업이 아니라 그림으로.

| 자리 비운 시간 | 문 앞 |
|---|---|
| ~1시간 | 가방 하나 |
| ~6시간 | 가방 셋, 사진 몇 장 |
| ~24시간 | 문 앞이 짐으로 가득, 쪽지 여러 장 |
| 48시간 (상한) | 더 안 쌓임 — "이제 그만 기다릴게요" |

`arrival_scene.gd` 의 돌아옴 연출과 `waiting_notes()` 를 그대로 재활용한다.
**상한은 벌이 아니라 다시 켤 이유**다. 수첩을 올리면 상한이 늘어난다.

## 5. 자동 출발 — 고르는 재미를 어떻게 지키나

여기가 이 기획의 유일한 위험 지점이다.
자동 출발을 켜면 플레이어가 아무것도 안 고르게 되고, 그러면 여행지 225곳이 그냥 숫자가 된다.

**해법 — 자동은 "반복"만 하고, "새 곳"은 사람이 고른다.**

| 여행 계획표 | 자동으로 하는 일 |
|---|---|
| 없음 | 아무것도. 매번 사람이 고름 |
| 1단계 | **다녀온 곳만** 자동 반복 (여비 벌이) |
| 2단계 | 시간당 여비가 가장 높은 곳을 골라 반복 |
| 3단계 | 자리 비운 사이 **새 곳 1곳까지** 알아서 감 |

즉 **여비는 자동으로 벌리고, 추억(새 곳)은 손으로 딴다.**
켜서 하는 일이 "새 곳 한 군데 골라 보내기"로 남는다 — 이게 이 게임의 하루 한 번이다.

새 곳 고르기는 앞 문서대로 **카드 3장**. 목록도 필터도 없다.

## 6. 다시 떠나기 (프레스티지)

방치형에는 리셋이 있어야 곡선이 다시 재밌어진다. 다만 힐링 게임이라 **말을 바꾼다.**

- 조건: 다른 차원에 다녀온 뒤 (또는 추억 50개 이상)
- 초기화: 여비, 업그레이드 전부
- **남는 것: 사진첩 전부.** 사진은 절대 안 지운다
- 얻는 것: 영구 배율 `1 + sqrt(추억) × 0.1`
  - 추억 50 → ×1.71 / 추억 100 → ×2.0 / 추억 225 → ×2.5

연출은 축포가 아니라 이렇게 둔다 — 짐을 다시 싸는 쿼카 커플, 한 줄:
> *"또 가고 싶어졌어요."*

## 7. 켜면 보이는 것

화면 **셋**. 하단 탭도 안 만들고, 집 화면에서 두 방향으로만 간다.

```
┌──────────────────────────┐
│  💰 1,240   ✨ 38/225     │  ← 자원 두 줄
│                          │
│    (하늘 — 지금 시각)     │
│      🚲 ← 여행 중         │
│  ══════════════════════  │
│   [남은 시간 12분]        │
│                          │
│  [ 사진첩 ]  [ 준비하기 ] │
└──────────────────────────┘
```

- **집** — 위 화면. 돌아와 있으면 문 앞에 짐이 쌓여 있고, 누르면 정산 연출
- **사진첩** — 격자. 맨 위 한 줄에 `다녀온 곳 38 / 225`
- **준비하기** — 업그레이드 다섯 줄 + 새 곳 카드 3장

기념품 3D 방, 통계 화면, 대륙 필터, 바람편지, 엽서 내보내기, 튜토리얼은 없앤다.

## 8. 0편

`redesign-simple.md` 와 같다 — **픽셀 컷신 6장, 약 90초.** 대사는 한 줄도 안 바꾼다.
챙긴 물건 3개는 방치형에서 시작 업그레이드로 이어진다.

| 물건 | 방치형에서 |
|---|---|
| 📷 카메라 | 카메라 1단계 보유 상태로 시작 |
| 📓 수첩 | 오프라인 상한 2h 보유 |
| 🎒 가방 | 가방 1칸 |

없으면 0단계에서 시작한다. 이야기가 곧 튜토리얼이 된다.

## 9. 화풍 — 픽셀

`tools/pixel/pixelize.py`. 내부 480×216, 쿼카 키 약 38px, 기존 에셋에서 뽑은 32색.
있는 그림을 변환한다. 비용 드는 이미지 생성은 안 쓴다.

이동수단 7단계는 새 그림이 필요한데, 쿼카 스프라이트에 픽셀 탈것을 **코드로 얹는다**
(자전거·버스 창틀 정도는 도형으로 그린다). 외주도 생성도 없다.

## 10. 정직하게 — 이 방향의 위험

**(1) 방치형과 힐링은 사실 잘 안 맞는다.**
방치형은 "숫자가 오르는 쾌감", 힐링은 "아무것도 안 해도 되는 편안함"이다.
숫자를 크게 키우면 힐링이 죽고, 작게 두면 방치형이 심심하다.
→ 이 기획의 타협: **숫자는 여비 하나만 크게 키우고, 추억은 225로 유한하게 묶는다.**
화면에 큰 숫자가 하나만 보이게 한다.

**(2) 유한한 225곳과 무한한 여비는 언젠가 어긋난다.**
여비가 넘쳐도 갈 데가 없어지는 시점이 온다.
→ 그때가 "다시 떠나기" 시점이다. 어긋남을 리셋의 명분으로 쓴다.

**(3) 자동 출발이 게임을 껍데기로 만들 수 있다.**
→ 5절의 분리(여비는 자동, 새 곳은 수동)가 이 문제 전용 장치다. 여기가 무너지면 기획이 무너진다.

**(4) 여행 시간이 방치형 치고 너무 길다.**
지금 국내 30분~1시간 30분은 "확인하러 오는 게임"의 수치다. 방치형은 회전이 더 빨라야
업그레이드 체감이 난다.
→ **국내를 5~15분으로 줄이는 걸 권한다.** 해외 30분~2시간, 우주 3~6시간, 차원 12시간.
`DESTINATIONS` 의 `duration_sec` 만 고치면 되고 데이터 구조는 안 바뀐다.

## 12. 하게 되면 순서

1. `duration_sec` 재조정 (10절 (4)) — 데이터만 고치면 되니 제일 먼저, 되돌리기도 쉽다
2. 여비·업그레이드 상태 + 저장
3. 오프라인 정산 + 문 앞에 쌓이는 연출 (`arrival_scene.gd` 재활용)
4. 준비하기 화면
5. 자동 출발 (여행 계획표)
6. 다시 떠나기
7. 픽셀 화풍 적용, 0편 컷신 교체, 횡스크롤 삭제
8. 균형 조정 — 30일치를 빨리감기로 돌려 여비 곡선 확인

1~3만 해도 방치형으로 돌아간다. 4~6은 그 위에 얹는 것이므로 **중간에 멈춰도 게임이 된다.**
