# 쿼카 군단 - 판단 기준

`docs/redesign-lane.md` 는 **무엇을 바꿨는지**의 기록이다. 이 문서는 그 밑에 깔린 **왜**만 모은다.
새 기능·수치·화면을 고치기 전에 읽고, 기준과 부딪치면 기준부터 고칠지 사용자와 정한다.

## 바꾸기 전 세 질문

1. **왜 이 결과가 나왔나?** 사용자 사진·불만 하나는 증상이다. 원인을 찾는다.
   (예: 폰에서 자간이 벌어짐 → 옛 APK 테마 + Jua 에 없는 `·` 가 다른 글꼴로 샘. 화면 하나 고쳐서는 안 끝났다)
2. **어떤 기준이 숨어 있나?** 아래 기준 중 무엇에 걸리는지 이름을 붙인다. 없으면 새 기준이 필요한 일이다.
3. **다시 안 생기게 하려면?** 같은 실수가 두 번 나면 사람 눈 대신 **검사 도구**로 막는다 (아래 '지키는 장치').

## 장르에서 빌린 원리 (결과물 말고)

냥코식 한 줄 싸움이 재미있는 이유를 우리 말로 옮긴 것이다 (`docs/battlecats-research.md`). 이름·그림은 빌리지 않는다.

| 원리 | 우리 게임에서 | 확인 |
|---|---|---|
| 판 안의 선택은 **투자냐 지출이냐** 하나로 | 웃음을 수입에 쓰나, 쿼카를 내나 | SimLane: 봇이 수입을 안 올리면 늘 모자라다 |
| 유닛은 **역할**로 다르다 (숫자 차이 말고) | 벽·근접·범위·돌격·원거리·거대 | 원거리 벌레는 근접만으로 못 잡는다 |
| 전선이 **출렁여야** 보는 맛이 있다 | 넉백, 우두머리 충격파, 바주카 | TraceLane 으로 한 판 그대로 보기 |
| 겉은 단순, 속은 깊다 | 버튼 몇 개 + 편성·타이밍 | 처음 안내가 짧은가 |
| **돈 안 써도 다 깬다** | 현금 결제·광고 없음, 뽑기는 게임 재화만 | 경제 점검 표 |
| 다음이 궁금하다 | 새 친구·진화·보물·꽃 | 판마다 받는 것이 있는가 |

## 우리 기준

1. **멈추지 않고 끝까지.** 막히는 판보다 쉬운 판이 낫다. 1장 100판 ≈ 1시간 (`PACE`·`NEST_MULT`·`CH1_BUG`).
   어려움은 꽃 셋째 송이와 오늘의 도전이 맡는다.
2. **손으로 한 플레이에 보상한다.** 자동 소환은 사라질 것이다. 재미가 자동에 기대면 안 된다 (손맛 보너스·꽃·임무).
3. **벌이 없다, 놓쳐도 잃지 않는다.** 연속 출석 초기화·시간 압박을 만들지 않는다 (선물 달력은 끊겨도 이어진다).
4. **영구 힘은 아껴 준다.** 공격·체력 % 를 주는 보상은 밸런스를 흔든다. 넣으면 SimLane 을 다시 돌린다.
5. **수치는 시뮬레이션으로 정한다.** 감으로 바꾸지 않는다. SimLane 두 씨앗(7·11) 결과를 문서에 남긴다.
   기획 문서의 숫자에는 출처를 붙인다: `[S1]`(출처), `[가정]`(우리가 정한 값), `[추정]`(계산값, 식과 함께). 아무 표시 없는 숫자는 쓰지 않는다.
6. **읽혀야 한다 (폰 기준).** 개발 PC 화면은 믿지 않는다. 글꼴은 Jua 한 벌, 없는 글자는 기호 글꼴에 직접 그린다.
   구역·물건 이름에 Jua 에서 헷갈리는 받침(밭·밑 같은 ㅌ)을 피한다.
7. **크기는 단계로.** 글 크기 18 · 22 · 28 · 34 · 44, 50 이상은 숫자·큰 제목. 화면마다 새 숫자를 고르지 않는다.
   테두리는 `IdleUi.outline_for(fs)` 한 곳.
8. **버튼은 위계로.** 주 버튼 하나(진한 색), 안전한 버튼은 흰색(ghost), 위험한 버튼은 흰 바탕 + 빨간 테두리.
   모자란 버튼은 흐리게 하지 않는다 - 숫자가 읽혀야 한다.
9. **색 금지:** 노랑·산호색은 UI 에 쓰지 않는다. 바탕 라벤더, 새것은 벚꽃 분홍.
10. **우리 것만.** 배틀캣 이름·그림, 실제 상표를 흉내 내지 않는다. 유료 에셋·폰트·API 를 쓰지 않는다.
11. **저장은 잃지 않게.** 앱을 지우거나 폰을 바꿔도 모은 것을 되찾을 길이 있어야 한다 (같은 장르 리뷰의 큰 불만 - `docs/lane-premortem.md`).
    지금은 설정 창의 저장 코드(`LaneState.export_code`). 새 저장 항목은 `to_dict` 에 넣으면 코드에도 저절로 실린다.

## 지키는 장치 (사람 눈 대신)

| 장치 | 막는 것 | 생긴 계기 |
|---|---|---|
| `tools/pixel/check-font-glyphs.py` | 폰트에 없는 글자, 다른 글꼴로 새는 글자 | `—` 네모 상자, `·` 자간 |
| `tools/pixel/check-font-sizes.py` | 글 크기 단계 밖 숫자가 늘어나기 (기준선 래칫) | 크기 22가지 (2026-11 아트 검토) |
| `tests/TestLane.tscn` | 규칙·저장·보상 회귀 | |
| `tools/sim/SimLane.tscn` | 판 길이·난이도 곡선 | 1장 7시간 → 1시간 |
| `IdleUi.refresh_project_theme()` | 폰이 옛 APK 테마를 쓰기 | 0.1.280 |

**같은 종류의 문제가 두 번 나오면 이 표에 한 줄을 더하는 것**이 그 일의 끝이다.

## 아직 기준이 약한 곳 (다음에 정할 것)

- 리뷰 분석 · 프리모템 · 가설 표는 `docs/lane-premortem.md` (2026-11-16). 큰 결정 전에 가설 표부터 본다.

- 화면 배치: 창 제목·닫기 버튼 모양이 창마다 다르다. 공용 창 틀 하나로 모을 것.
- 글 크기: 단계 밖 76곳이 남아 있다 (20·24·26·30 이 많다). 화면을 고칠 때마다 단계로 옮기고 기준선을 낮춘다.
- 사진 검사: 화면 찍기는 손으로 한다. 주요 화면 몇 장을 자동으로 찍어 넘침·잘림을 보는 장치가 없다.
